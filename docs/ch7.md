# CHAPTER 7. 하네스로 기획 검증 자동화하기

> Claude Code의 멀티 에이전트 아키텍처(Harness 패턴)를 활용해 기획 검증 프로세스를 자동화했습니다.

## 배경 — 기획 검증에 쓰는 시간을 줄일 수 있다면

기획한 기능과 서비스, 정의한 정책 문서가 실제 개발에 잘 반영되었는지 확인하는 것은 기획자의 중요한 역할입니다. 저는 이 기획 검증을 늘 꼼꼼하게 직접 해왔습니다.

문제는 시간이었습니다. 정책 문서와 실제 동작을 하나씩 대조하고, 엣지 케이스를 찾고, 결과를 정리하는 과정은 릴리즈 직전마다 상당한 리소스를 요구했습니다.

그래서 생각했습니다. **이 과정을 Harness 패턴으로 구조화할 수 있다면?**

> **핵심 가설**
> QA팀의 검증 기간을 줄이는 것은 곧 서비스 전체 릴리즈 리소스를 줄이고 협업 효율을 높이는 방향입니다.
> 기획자가 QA 전 단계에서 더 빠르고 명확하게 검증할 수 있다면, QA팀이 FE/BE와 주고받는 추가 커뮤니케이션 비용도 함께 줄어듭니다.

## 기존 프로세스의 문제

| 단계 | 내용 | 문제 |
|---|---|---|
| 기획 완료 | 기능 정의 + 정책 문서 작성 | - |
| 개발 | FE/BE 구현 | - |
| 기획 검증 | 기획자가 직접 정책 대조 + 케이스 확인 | **시간 소요 ↑** |
| QA | QA팀 공식 검증 | **이슈 발견 → FE/BE 재수정** |
| 재검증 | 수정 후 재확인 | **릴리즈 지연** |
| 릴리즈 | 배포 | - |

## 하네스(Harness)란

Claude Code의 멀티 에이전트 패턴으로, 여러 에이전트가 역할을 나눠 하나의 목표를 수행합니다. 기획 검증에 적용하면 입력 문서를 분석하고, 정책과 실제 구현을 대조하며, 이슈를 자동으로 리포트로 정리합니다.

## 입력 문서 구성

| 문서 유형 | 내용 |
|---|---|
| **기획 문서** | 기능 정의, 화면 구조, 동작 흐름 |
| **정책 문서** | 예외 처리, 엣지 케이스, 유효성 조건 정의 |
| **타사 벤치마킹 테스트 결과** | 경쟁사 동일 기능 동작 방식과 비교 분석한 결과 |
| **수동 테스트 결과** | 기획자가 직접 케이스별로 수행한 테스트 결과 기록 |

## 에이전트 구조 설계

**에이전트 (5개) — 누가 할 것인가**

- `spec-reader` — 기획서·정책 문서 파싱 및 검증 기준 추출
- `benchmark-analyst` — 타사 벤치마킹 결과 분석 및 기준 대조
- `test-validator` — 수동 테스트 결과와 정책 기준 대조 검증
- `issue-reporter` — 불일치 항목 자동 이슈 리포트 생성
- `qa-checklist-generator` — QA팀 전달용 체크리스트 자동 생성

**실행 흐름**

```
입력 문서 (기획서 + 정책 + 벤치마킹 + 수동 테스트)
→ spec-reader: 검증 기준 추출
→ benchmark-analyst + test-validator: 병렬 대조 분석
→ issue-reporter: 이슈 목록 생성
→ qa-checklist-generator: QA팀 전달 체크리스트 출력
```

## 실전 적용 결과

| 항목 | 내용 |
|---|---|
| **선제 이슈 발견** | QA 전달 전 기획자 단계에서 정책 불일치 및 누락 케이스 사전 식별 |
| **QA 커뮤니케이션 감소** | FE/BE와의 추가 이슈 논의 횟수 감소 — 검증 완성도가 높아진 상태로 QA 진입 |
| **릴리즈 속도 향상** | 재검증 사이클 감소로 전체 릴리즈 리드타임 단축 |
| **품질 기준 명문화** | 하네스 실행 결과가 검증 기록으로 남아 다음 기획 사이클에도 활용 |

## Before / After

| 항목 | Before | After |
|---|---|---|
| 기획 검증 방식 | 정책 문서와 실제 동작 수동 대조 | 하네스가 자동 대조 후 이슈 리포트 생성 |
| 기획 검증 소요 시간 | 케이스당 수 시간 | **문서 투입 후 즉시 결과 출력** |
| QA팀 진입 전 완성도 | 기획자 수동 검증 수준 | 정책 전체 항목 대조 완료 상태로 전달 |
| QA↔FE/BE 커뮤니케이션 | 이슈 발견 후 반복 논의 | **선제 해결로 추가 논의 최소화** |
| 전체 릴리즈 프로세스 | 기획 → 개발 → QA → 재수정 → 재검증 → 릴리즈 | 기획 → 하네스 검증 → 개발 → QA → 릴리즈 |
