# 📖 들어가며 (Prologue)

> 비개발자를 위한 AI 업무 자동화 실전 가이드

## 이 백서를 쓰게 된 이유

솔직히 말하면, 처음엔 Claude Code가 기획자한테 맞는 툴인지 확신이 없었습니다.

터미널 기반이고, CLI 명령어를 직접 입력해야 하고, 개발자 냄새가 짙게 났거든요. 그런데 막상 써보니 달랐습니다. 매일 반복하던 회의록 정리, Jira 티켓 등록, API 검증 — 이 작업들이 하나씩 사라지기 시작했습니다.

저는 카카오클라우드 서비스 기획자입니다. 개발 경험이 있고, 코드를 읽고 분석할 수 있으며, API·SDK 검증을 기획 단계에서 직접 해왔습니다. 그 배경 덕분에 Claude Code를 더 깊이 쓸 수 있었는지도 모릅니다. 하지만 이 백서는 그런 배경이 없는 분들도 충분히 따라올 수 있도록 썼습니다.

> 이 백서는 "AI가 이런 것도 된다"는 소개서가 아닙니다. 제가 실제로 쓴 프롬프트, 겪은 오류, 해결한 방법, 그리고 그게 실제로 업무에 어떤 변화를 만들었는지를 기록한 **실전 노트**입니다.

## 왜 Claude Code인가

여러 AI 툴을 써봤습니다. 챗봇 형태는 대화로 끝나고, 결과물을 어딘가에 붙여넣는 게 또 일이었습니다.

Claude Code는 달랐습니다. MCP로 Confluence에 직접 문서를 쓰고, Jira에 티켓을 만들고, Figma 컴포넌트를 읽어오고, GitHub에 커밋까지 — 대화가 아니라 실제로 실행이 됩니다. 기획자 입장에서 "AI한테 시켰더니 진짜로 됐다"는 경험은 생각보다 큰 차이입니다.

> **Claude Code를 선택한 이유를 한 줄로 정리하면**
> 결과물이 내 손을 거치지 않고 시스템에 직접 반영된다는 것.

## 이 백서의 구성

각 챕터는 독립적으로 읽을 수 있습니다. 관심 있는 챕터부터 바로 펼쳐도 됩니다.

| 챕터 | 주제 | 핵심 내용 |

| **CH.0** | 기획자에게 Claude Code가 필요한 이유 | 도입 배경, 기대 효과 |
| **CH.1** | 환경 구축 | 설치, MCP 연동 세팅 |
| **CH.2** | 반복 업무의 종말 | 자동화 대상 발굴, Before/After |
| **CH.3** | MCP Confluence 연동 | 회의록·기획서·스펙 문서 자동화 |
| **CH.4** | MCP Jira 연동 | 티켓 생성·관리 자동화 |
| **CH.5** | MCP Figma 연동 | 기획 화면 시안 제작 |
| **CH.6** | 카카오클라우드 사용자 가이드 작성 | KC-docs 기반 초안 자동 생성 |
| **CH.7** | 하네스로 기획 검증 자동화하기 | Harness 패턴으로 기획 검증 자동화 |
| **CH.8** | API 자동화 테스트 툴 구축 | Swagger JSON → 자동화 테스트 툴 |

## 이런 분께 도움이 됩니다

- Claude Code를 업무에 써보고 싶은데 어디서 시작할지 모르는 **기획자·PM**
- Confluence, Jira, Figma를 매일 쓰면서 반복 작업이 쌓여가는 **실무자**
- AI 툴 도입을 검토 중인 **팀 리드·매니저**

> 이 백서는 완성된 가이드가 아니라, 현재도 진행 중인 실험의 기록입니다. 틀린 방법도 있고, 더 나은 방법도 생겼습니다. 그 과정 자체를 담았습니다.
