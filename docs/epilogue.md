# 🎯 나오며 (Epilogue)

> 시도해봤던 것, 효율성이 있었던 것, 앞으로 활용성이 있을 것들.

## 시도해봤던 것들

CH.0부터 CH.9까지 실제로 시도한 것들을 돌아보면 세 가지 유형으로 나뉩니다.

### ① 연결 — 업무 도구를 Claude Code에 붙이는 시도

| 시도 | 결과 |
|---|---|
| Confluence MCP 연동 (사내 SSL 이슈 포함) | 트러블슈팅 끝에 안정적 연동 완료 |
| Jira MCP 연동 | Confluence와 동일 서버로 동시 연동 |
| Figma MCP 연동 | 읽기 전용이지만 컴포넌트 분석에 충분히 활용 |
| KakaoCloud MCP Hub 연동 | 사내 서비스 전용 컨텍스트 확보 |
| GitHub MCP (개인 + 사내 이중 구성) | kc-docs 작업에 즉시 활용 |

### ② 자동화 — 반복 업무를 없애는 시도

회의록 작성, 스펙 문서 수정, Jira 티켓 등록, 경쟁사 분석 보고서 초안 생성. 처음엔 "이게 될까?" 싶었지만, 실제로 해보니 될 뿐 아니라 더 빠르고 일관성 있게 됐습니다.

### ③ 구축 — 없는 툴을 직접 만드는 시도

API 자동화 테스트 툴(kc-analytics-api-tester)을 단일 HTML에서 시작해 멀티 에이전트 아키텍처로 발전시키고 Render에 배포하기까지. 기획자가 할 수 있을 거라고 생각하지 못했던 일들이었습니다.

## 실제로 효율성이 있었던 것들

모든 시도가 처음부터 효율적이지는 않았습니다. 시행착오도 있었고, 기대보다 덜 빠른 경우도 있었습니다. 아래는 효율이 명확하게 증명된 것들입니다.

| 영역 | 효율성이 높았던 이유 |
|---|---|
| **회의록 → Confluence 자동 업로드** | 반복 패턴이 명확하고 형식이 정해져 있어 자동화 적합도 높음 |
| **Jira 티켓 일괄 생성** | 회의 액션 아이템을 한 번에 처리 — 클릭 수 대폭 감소 |
| **kc-docs 릴리즈 노트 한/영 동시 작성** | 파일 구조 파악 후 동기화까지 자동 처리 |
| **API 테스트 툴 구축** | 30개 API 등록이 1분으로 — 반복 작업의 완전한 제거 |
| **판가 제안서 차트·대시보드 생성** | 수치 계산·시각화를 맡기고, 기획자는 전략과 검수에 집중 |

> 반복 빈도가 높고, 판단보다 실행이 많고, 형식이 정해진 업무일수록 효율이 높았습니다.
> 반대로 이해관계자 설득, 서비스 방향 결정 같은 업무는 여전히 사람의 영역이었습니다.

## 앞으로 활용성이 있을 것 같은 것들

| 방향 | 내용 |
|---|---|
| **기획 어시스턴트 고도화** | 팀 전체가 공유하는 CLAUDE.md + 커스텀 명령어 체계로 발전. 신규 팀원 온보딩에도 활용 가능 |
| **스펙 변경 자동 추적** | API 스펙 변경 시 관련 Confluence 문서, Jira 티켓, kc-docs까지 연쇄 업데이트 반자동화 |
| **API 테스트 툴 확장** | kc-analytics-api-tester를 다른 카카오클라우드 서비스로 확장. Swagger JSON만 있으면 즉시 적용 가능 |
| **릴리즈 노트 → 공지문 자동 변환** | kc-docs 릴리즈 노트 작성 후 사용자 공지문·내부 공유 문서로 자동 변환하는 흐름 구성 |
| **제안서 템플릿화** | 이번 판가 제안서 경험을 바탕으로, 다음 보고 자료는 검수 기준과 차트 구조를 미리 잡아두고 시작 |

## 함께 시작해볼 분들을 위한 체크리스트

- ☐ 가장 귀찮은 반복 업무 하나 선정
- ☐ MCP 하나만 연동해서 그 업무부터 자동화
- ☐ CLAUDE.md에 내 프로젝트 컨텍스트 작성
- ☐ 가장 자주 쓰는 프롬프트를 커스텀 명령어로 등록
- ☐ 한 달 후 Before/After 기록
